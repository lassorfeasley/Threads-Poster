North star

Keep improving the product as a local web UI (easy UX iteration). When distribution matters, package the same stack as a Mac app so customers never touch Python, yt-dlp, ffmpeg, or Whisper — those still run on their machine. Longer term: optional cloud for always-on publishing, shared workspaces, and fuller autopilot. Prefer notarized direct download over Mac App Store; do not plan a Swift rewrite.

Autonomy goal: the app can operate a Threads account (queue, schedule, engage) with human taste checks as needed. Local media creation and cloud/always-on publishing can stay split — same shape as today’s local factory + headless publisher.

Phase 0 — Now

Single-operator, localhost. Polish in place.

  • Doing
    UI / UX polish Ship small improvements daily in the existing FastAPI + Jinja UI. This is the product UI.
  • Next
    Configurable workspace / brand in-app Entity name, mission/topic, audience, voice notes, keywords, categories, brand colors/fonts, standing first-reply — editable in the UI. Parameterize LLM prompts instead of hardcoding climate / local-TV / Renewables.org. Improves today’s use even before selling.
  • Next
    RSS for channel monitoring Replace recurring YouTube Data API playlist polling with free channel RSS. Keep Data API (or yt-dlp metadata) for one-time channel resolve and durations. Cuts quota and key friction.
Phase 1 — Distribute as a Mac app

Same local pipeline; hide the plumbing. Build when UX feels solid — not before.

  • Later
    Package with Tauri, Electron, or py2app Double-clickable .app that starts the Python backend and shows this UI (WebView or window). Bundle ffmpeg / yt-dlp; download Whisper weights on first run if needed. Sign + notarize for Gatekeeper.
  • Later
    Auto-update Electron-updater, Tauri updater, or Sparkle (if py2app). Customers get new UX without git. Direct download (site / Gumroad / etc.), not App Store as the default.
  • Later
    Licensing / seats (solo first) Simple paid license is enough for v1. Multi-seat collaboration waits on Phase 2.
Phase 2 — Autopilot & optional cloud

Run the account with less babysitting; keep scrape/Whisper local unless a deliberate decision says otherwise.

  • Later
    Stronger unattended publishing Durable queue + scheduler so the account keeps posting when the operator isn’t clicking. Mac-on is fine for early autopilot; cloud worker (like today’s Fly / Actions path) for set-and-forget.
  • Later
    Shared workspaces (if teams matter) User accounts → workspace owns channels, brand, and one Threads connection. Local apps claim download/trim jobs and upload finished clips. Triage can be multiplayer; media stays on someone’s machine.
  • Later
    Meta App Review (if customers connect their own Threads) Required to leave “testers only” on a Meta developer app. Can run in parallel with packaging.
Explicitly out of scope (for now)
  • No
    Full Swift rewrite / App Store as north star Native Swift UI does not replace the Python media stack. App Store sandbox fights yt-dlp/ffmpeg and third-party YouTube downloading. Notarized DMG first; Store only as a later experiment with a stripped feature set if ever.
  • No
    Hosted YouTube downloading as the default product Seamless zero-install SaaS that silently mirrors arbitrary channels means your servers run yt-dlp — ToS, blocking, and legal posture change. Prefer local (Mac app) creation. Upload-own-content SaaS is a different product if zero-install ever becomes the priority.
  • No
    Separate “companion app” while still selling pure hosted web Unnecessary if the Mac app is the product. A browser-only hosted UI plus a side agent is the fallback if we ever need teams-on-web with local media — not the plan for v1.
Why local scrape / Whisper still “feel” seamless

Today you never “installed a companion” because you are the runtime (python run.py dashboard). A packaged Mac app preserves that: one install, browser-shaped UI, heavy work on-device. Customers should not need multiple product accounts for the core loop — Threads (and later YouTube) show up as connected integrations on one workspace.
